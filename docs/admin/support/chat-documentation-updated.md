# Чаты — Admin Panel documentation

## Scope

- Продукт: Trade Taxi
- Область: Admin Panel
- Платформа: Web
- Страница: `Чаты / Поддержка`
- Scope: список чатов, поиск, создание диалога, чат, сообщения, изображения, Reply, Copy, unread, фильтры, пагинация и real-time обновления

---

## Overview

Страница `Чаты / Поддержка` используется сотрудниками поддержки для коммуникации с водителями.

На странице администратор может:

- работать с существующими диалогами;
- находить существующий чат по ФИО водителя;
- просматривать историю переписки;
- отправлять текстовые сообщения и изображения;
- отвечать на конкретные сообщения через Reply;
- переходить из Reply к исходному сообщению;
- фильтровать список чатов;
- видеть количество непрочитанных сообщений;
- переходить из чата в карточку водителя.

Список чатов и открытый чат обновляются в real time без ручного обновления страницы.

---

## List of chats

В списке отображаются только водители, с которыми уже существует диалог.

Для каждого чата отображаются:

- фамилия и инициалы водителя;
- аватар;
- инициалы ФИО внутри аватара;
- цветная обводка аватара;
- preview последнего сообщения;
- количество непрочитанных сообщений данного чата, если они есть.

Цвет обводки аватара соответствует текущему статусу водителя.

Если последним сообщением является изображение, вместо текста сообщения в preview отображается `Фото`.

Выбранный чат визуально выделяется.

### Сортировка

Чаты сортируются по времени последнего сообщения.

Чат с самой новой активностью находится сверху списка.

Любое новое сообщение изменяет позицию чата:

- сообщение водителя;
- сообщение администратора;
- изображение;
- Reply.

После нового сообщения соответствующий чат поднимается наверх.

### Pagination

Список чатов загружается постранично.

Текущий API использует параметры `page` и `per_page`. В текущем запросе используется `per_page=50`.

При загрузке следующей страницы ранее загруженные чаты остаются в списке.

Real-time обновления не должны приводить к дублированию или потере чатов при уже загруженных нескольких страницах.

---

## Search

Поиск выполняется по **любой части ФИО водителя**.

Поддерживается поиск:

- по полному ФИО;
- по фамилии;
- по имени;
- по отчеству;
- по части фамилии, имени или отчества;
- по комбинации частей ФИО.

Поиск выполняется по существующим чатам, а не только по уже загруженной странице списка.

Водитель, с которым ещё нет диалога, через поиск страницы чатов не отображается.

Чтобы администратор первым написал такому водителю, необходимо перейти на страницу водителя и открыть диалог оттуда.

---

## Chat creation

### Первое сообщение водителя

Диалог автоматически появляется после первого сообщения водителя.

После первого сообщения:

- создаётся один диалог с водителем;
- чат появляется в списке в real time;
- чат поднимается наверх;
- preview содержит первое сообщение;
- сообщение считается непрочитанным до открытия чата;
- счётчики unread обновляются.

Последующие сообщения водителя добавляются в тот же диалог и не создают новый чат.

### Первое сообщение администратора

Администратор может первым начать переписку с водителем.

Если диалога ещё нет, начать его необходимо со страницы водителя.

После отправки первого сообщения:

- создаётся диалог;
- он появляется в списке чатов;
- чат поднимается наверх;
- preview содержит сообщение администратора.

Повторный переход к переписке с тем же водителем должен открывать существующий диалог, а не создавать новый.

---

## Chat header

В шапке открытого чата отображаются:

- полное ФИО водителя;
- мобильный телефон;
- номер автомобиля;
- статус водителя.

Если автомобиль не привязан, вместо номера отображается `-`.

Данные в шапке относятся к текущему открытому водителю и должны обновляться при переключении между чатами.

### Переход в карточку водителя

ФИО водителя в шапке является кликабельным.

По клику открывается страница соответствующего водителя.

---

## Message history

В открытом чате отображается история переписки с выбранным водителем.

Сообщения располагаются в хронологическом порядке.

Входящие и исходящие сообщения визуально различаются согласно дизайну.

Поддерживаются:

- текстовые сообщения;
- изображения;
- Reply-сообщения.

История сообщений загружается постранично при прокрутке вверх.

При подгрузке более старых сообщений текущая история не должна теряться, дублироваться или менять хронологический порядок.

Scroll position после подгрузки старых сообщений должен оставаться корректным.

---

## Text messages

Администратор может отправлять текстовые сообщения водителю.

Максимальная длина сообщения — **1000 символов включительно**.

Допустимо:

- сообщение от 1 символа;
- сообщение ровно из 1000 символов.

Сообщение более 1000 символов отправляться не должно.

Пустое сообщение и сообщение, состоящее только из пробелов, не должны отправляться.

После успешной отправки:

- сообщение появляется в текущем чате;
- composer очищается;
- preview последнего сообщения обновляется;
- чат поднимается наверх списка.

---

## Images

Поддерживается отправка изображений.

### Допустимые форматы

- `jpg`
- `jpeg`
- `png`
- `webp`

### Ограничение размера

Максимальный размер изображения — **≤ 10 MB**.

Изображение размером ровно 10 MB допустимо.

Изображение размером более 10 MB должно быть отклонено.

Ограничение применяется ко всем поддерживаемым форматам.

Изменение расширения файла не должно позволять обойти ограничения формата или размера.

### Отображение

Изображения должны сохранять корректные пропорции и не ломать layout чата.

Если изображение является последним сообщением диалога, в списке чатов отображается `Фото`.

---

## Unread messages

В интерфейсе используются два разных типа счётчиков.

### Counter в строке чата

Счётчик в строке конкретного чата показывает **количество непрочитанных сообщений этого чата**.

Например, если водитель отправил 5 сообщений и чат ещё не был открыт, в строке чата отображается `5`.

### Counter в боковом меню

Счётчик в боковом меню показывает **количество чатов, в которых есть хотя бы одно непрочитанное сообщение**.

Он не показывает суммарное количество всех непрочитанных сообщений.

Пример:

- чат A — 5 непрочитанных сообщений;
- чат B — 2 непрочитанных сообщения;
- counter строки A — `5`;
- counter строки B — `2`;
- counter бокового меню — `2`.

### Read state

Сообщения считаются прочитанными **при открытии чата**.

При открытии чата:

- непрочитанные сообщения этого чата становятся прочитанными;
- counter строки чата сбрасывается;
- counter бокового меню уменьшается на один чат, если в нём больше не осталось unread.

Если новое сообщение приходит в чат, который уже открыт администратором, сообщение сразу считается прочитанным.

В этом случае:

- counter строки не увеличивается;
- counter бокового меню не увеличивается.

## Message actions

### Context menu

Контекстное меню сообщения открывается:

- по long press;
- по right click.

Доступные действия:

- `Ответить`;
- `Скопировать`.

Меню закрывается после выбора действия или согласно стандартному поведению UI.

## Reply

Администратор может ответить на конкретное сообщение водителя или администратора.

После выбора `Ответить` над composer появляется reply-preview исходного сообщения.

В preview отображаются:

- автор исходного сообщения;
- содержимое исходного сообщения;
- кнопка `×` для отмены Reply.

Для длинного текста используется предусмотренное дизайном сокращение/ограничение отображения.

### Отмена Reply

Кнопка `×` отменяет Reply.

При отмене:

- связь с исходным сообщением удаляется;
- уже введённый текст composer сохраняется;
- следующее обычное сообщение отправляется без цитаты.

### Отправка Reply

После отправки Reply:

- новое сообщение содержит цитату исходного сообщения;
- отображается автор исходного сообщения;
- отображается содержимое исходного сообщения;
- под цитатой отображается текст ответа;
- reply-preview очищается;
- composer очищается.

Reply должен сохранять связь с исходным сообщением после reload страницы и повторного открытия чата.

### Переход к исходному сообщению

Цитата Reply кликабельна.

По клику пользователь должен перейти к исходному сообщению.

Если исходное сообщение уже загружено, выполняется scroll к нему.

Если исходное сообщение находится в более старой, ещё не загруженной части истории, необходимые сообщения должны быть подгружены, после чего выполняется переход к исходному сообщению.

Связь должна выполняться по идентификатору сообщения, а не по совпадению текста.

---

## Reply to image

На сообщение с изображением также можно ответить через Reply.

В Reply отображается thumbnail исходного изображения.

Thumbnail должен:

- быть компактнее полноценного изображения сообщения;
- сохранять корректные пропорции;
- корректно отображать portrait, landscape и square изображения;
- не увеличиваться до размера исходного изображения из-за большого разрешения оригинала;
- не ломать layout Reply.

Клик по цитате с изображением переводит к исходному сообщению с фото.

### TBD by Design

Точный размер thumbnail пока не утверждён.

До утверждения конкретных размеров проверяются:

- визуальная компактность;
- сохранение aspect ratio;
- отсутствие растягивания;
- отсутствие поломки layout;
- единообразное отображение разных пропорций изображения.

Очевидно чрезмерное превью, фактически дублирующее полноразмерное изображение, требует согласования с дизайном.

---

## Copy

При выборе `Скопировать`:

- текст сообщения копируется в буфер обмена;
- контекстное меню закрывается;
- отображается тост `Текст скопирован`;
- тост отображается около 2 секунд.

Копируется текст самого сообщения без дополнительных UI-элементов и служебных символов.

---

## Composer state when switching chats

Draft-состояние между чатами не сохраняется.

При переключении с одного чата на другой:

- введённый, но не отправленный текст сбрасывается;
- активный Reply сбрасывается.

При возврате в предыдущий чат draft и незавершённый Reply не восстанавливаются.

Данные одного чата не должны переноситься в composer другого чата.

## Filters

На странице доступна кнопка `Фильтры`.

Панель содержит:

- `Статус водителя`;
- toggle `Непрочитанные сообщения`;
- `Сбросить`;
- `Применить`;
- кнопку закрытия `×`.

### Статус водителя

`Статус водителя` поддерживает множественный выбор.

Можно выбрать один или несколько статусов.

Несколько выбранных статусов объединяются по логике **OR**.

Пример:

`registration OR moderation`

### Непрочитанные сообщения

Фильтр представлен toggle `Непрочитанные сообщения`.

По умолчанию toggle выключен.

При выключенном toggle фильтрация по unread не применяется.

При включённом toggle отображаются только чаты, содержащие непрочитанные сообщения.

На уровне API включённому toggle соответствует `has_unread=1`.

### Комбинация фильтров

Между группой статусов и unread применяется логика **AND**.

Пример:

`(registration OR moderation) AND has_unread`

Пример структуры API-запроса:

`/api/support/chats?page=1&per_page=50&driver_statuses[]=registration&driver_statuses[]=moderation&has_unread=1`

---

## Apply filters

`Применить`:

- применяет выбранные условия;
- закрывает панель;
- обновляет список чатов;
- сбрасывает pagination на первую страницу.

Если подходящих чатов нет, отображается empty state.

---

## Cancel filter changes

Закрытие панели через `×` отменяет все изменения, сделанные после последнего Apply.

Если до открытия панели уже существовали применённые фильтры, после изменения значений и закрытия через `×` остаётся ранее применённое состояние.

При повторном открытии панели должны отображаться именно применённые значения, а не отменённые изменения.

---

## Reset filters

`Сбросить` возвращает фильтры в default state:

- выбранные статусы очищаются;
- toggle `Непрочитанные сообщения` выключается;
- pagination возвращается на первую страницу;
- после применения сброса отображается нефильтрованный список.

---

## Filter persistence

Применённые фильтры **не сохраняются после reload страницы**.

После reload:

- статусы не выбраны;
- `Непрочитанные сообщения` выключен;
- отображается нефильтрованный список.

---

## Unread filter and read state

При включённом фильтре `Непрочитанные сообщения` отображаются только чаты с unread.

При открытии такого чата его сообщения становятся прочитанными.

Поскольку после этого чат перестаёт соответствовать активному фильтру:

- открытый чат закрывается;
- чат исчезает из отфильтрованного списка;
- unread counters обновляются.

Если это был последний чат с unread, отображается empty state.

Если в закрытый read-чат приходит новое сообщение, чат снова становится unread и появляется в отфильтрованном списке в real time.

---

## Real-time updates

Страница должна обновляться без ручного reload.

### Открытый чат

Если сообщение приходит в текущий открытый чат:

- оно появляется в истории;
- появляется только один раз;
- сохраняется правильный порядок сообщений;
- preview списка обновляется;
- чат поднимается наверх;
- сообщение сразу считается прочитанным;
- unread counters не увеличиваются.

### Закрытый чат

Если сообщение приходит в другой чат:

- preview обновляется;
- чат поднимается наверх;
- counter строки увеличивается на количество новых непрочитанных сообщений;
- при первом unread этого чата counter бокового меню увеличивается на один чат.

Последующие непрочитанные сообщения этого же чата увеличивают только counter строки и не увеличивают количество unread-чатов в боковом меню.

### Новый диалог

Первое сообщение водителя создаёт новый чат, который появляется в списке без reload.

---

## Pagination and real-time

Real-time обновления и pagination должны работать совместно.

Новое сообщение во время загрузки следующей страницы не должно:

- создавать дубликат чата;
- удалять другие чаты;
- приводить к пропуску записей;
- нарушать сортировку.

Если новое сообщение приходит в чат, находившийся на более старой странице списка, этот чат должен переместиться наверх согласно времени последнего сообщения.

---

## Error handling

Ошибки API не должны создавать ложное успешное состояние.

В частности:

- неуспешно отправленное сообщение не должно выглядеть успешно доставленным;
- неуспешный Reply не должен выглядеть успешно отправленным;
- ошибка загрузки следующей страницы не должна удалять уже загруженные данные;
- ошибка загрузки истории не должна смешивать сообщения разных чатов;
- после восстановления соединения real-time механизм должен восстановить работу согласно реализации.

---

## Data isolation and race conditions

Данные разных чатов не должны смешиваться.

При быстром переключении между чатами поздний response предыдущего чата не должен перезаписывать данные текущего.

Особенно критичны сценарии:

- быстрое переключение `A → B → C`;
- загрузка истории A и переход в B до завершения запроса;
- быстрые последовательные поисковые запросы;
- последовательное применение разных фильтров;
- pagination одновременно с incoming message;
- Send одновременно с real-time echo;
- incoming message одновременно со сменой чата.

Real-time echo собственного сообщения не должен приводить к отображению сообщения дважды.

---

## Security

Пользовательский контент должен отображаться безопасно.

HTML/JavaScript, переданный внутри текста сообщения, не должен исполняться.

В частности, не должны выполняться:

- `<script>`;
- inline event handlers;
- другой пользовательский HTML/JS-код.

Reply должен ссылаться на сообщение того же диалога.

Сообщение не должно быть отправлено другому водителю из-за устаревшего состояния UI или race condition.

---

## Notes

- В списке чатов не выводятся бейджи `Новое` и `Нет ответственного`.
- Удаление сообщений через UI не предусмотрено.
- Максимальная длина текстового сообщения: **1000 символов**.
- Максимальный размер изображения: **≤ 10 MB**.
- Поддерживаемые изображения: **JPG, JPEG, PNG, WEBP**.
- Фильтры после reload возвращаются в default state.
- Draft и незавершённый Reply при переключении чатов сбрасываются.
- Точный размер thumbnail для Reply на изображение остаётся **TBD by Design**.
