# Документы водителя и деталка паспорта — Admin Web

## Область, источники и применение

- Trade Taxi, карточка водителя → `Документы` → паспорт. Актуализация: 15.10.2026.
- Источники: [задача #86eyr5r4x](https://app.clickup.com/t/90182809976/86eyr5r4x), ранее предоставленный PDF задачи, скриншоты и уточнения пользователя в чате Admin Web; существующие материалы Git по списку и истории.
- Последние уточнения пользователя имеют приоритет над прежними формулировками задачи. Правила ниже описывают требования, а не результат нового прогона админки.
- [Чек-лист списка](../../../checklists/admin/driver/documents-list-admin-checklist.md) и [чек-лист деталки паспорта](../../../checklists/admin/driver/86eyr5r4x-passport-details-admin-checklist.md) содержат проверки и отметки выполнения. Закрытые ранее блоки сохранены по сообщению пользователя; сборка и окружение того прогона не указаны.
- Вопросы `Q-PAS-*` и `Q-DOC-*` имеют статус **открыт** до явного ответа. Они не являются установленными правилами и не входят в число выполненных/невыполненных тестов. Условные сценарии ссылаются на их ID и получают ожидаемый результат после ответа.

## Список, статусы и зависимости

- Группы списка: `Основные`, `Иностранные`, `Дополнительные`.
- Статусы Admin Web: `Не загружено` и `Проверено {дата}`. `Обновлено` — устаревшее название для админки.
- Незаполненный паспорт: заголовок `Паспорт`, вместо реквизитов — прочерк. Заполненный: заголовок по стране; РФ — серия и номер, иностранный — номер. Формат даты рядом с `Проверено`: `ДД.ММ.ГГГГ`.
- Недоступные документы видимы и заблокированы. Уже загруженные файлы сохраняются.
- Паспорт РФ делает группу `Иностранные` недоступной.
- Наличие действующего основания ВНЖ/РВП у иностранного водителя блокирует `Патент`, `Чек об оплате патента`, `Амина`, `КИГ`. Что именно считается наличием основания, уточняется в Q-DOC-04.
- Снятие одного основания блокировки не отменяет остальные. Возврат к подходящей стране восстанавливает доступность только при отсутствии других оснований блокировки.
- Постоянная прописка находится внутри паспорта РФ. Временная регистрация — отдельный документ; изменение постоянной прописки её не перезаписывает.

Матрица подтверждённых ограничений (не полная матрица доступности всех документов):

| Сохранённое состояние | Группа `Иностранные` | Патент, чек оплаты патента, Амина, КИГ |
| --- | --- | --- |
| Паспорт РФ | Недоступна | Недоступны как документы этой группы |
| Иностранный паспорт, действует основание ВНЖ/РВП | Область блокировки всей группы — Q-DOC-02 | Заблокированы, файлы сохранены |
| Иностранный паспорт, основания ВНЖ/РВП нет | Ограничение РФ не применяется | Эти два основания не блокируют; другие правила — Q-DOC-05 |
| РФ → иностранный, основание ВНЖ/РВП остаётся | Ограничение РФ снимается | Блокировка по ВНЖ/РВП остаётся |

Дата `Проверено` и правила её обновления — Q-DOC-03. Отображение сохранённого статуса во время несохранённого редактирования само по себе не подтверждает сохранение черновика.

## Страны, форма и поля паспорта

Список стран по алфавиту: Азербайджан, Армения, Беларусь, Грузия, Казахстан, Россия, Таджикистан, Туркменистан, Узбекистан, Украина. Ниже «иностранный» означает девять перечисленных стран, кроме России.

Обозначения: **О** — обязательное поле; **Н** — необязательное; **—** — неприменимо. Это базовый состав по задаче и уточнениям; возможные исключения по конкретной стране или форме требуют ответа Q-PAS-29.

| Поле | РФ | Иностранная книжка | Иностранная ID-карта |
| --- | --- | --- | --- |
| Страна | О | О | О |
| Фамилия | О | О | О |
| Имя | О | О | О |
| Отчество | Н | Н | Н |
| Дата рождения | О | О | О |
| Место рождения | О | О | О |
| Серия | О | — | — |
| Номер | О | О | О |
| Пол | О | О | О |
| Когда выдан / дата выдачи | О | О | О |
| Кем выдан | О | О | О |
| Код подразделения основного паспорта | О | — | — |
| Действителен до / срок действия до | — | О | О |

Переключатель иностранного паспорта: `Книжка` / `ID-карта`. У книжки одно обязательное вложение `Основная страница`; у ID-карты обязательны `Лицевая сторона` и `Оборотная сторона`. Сохранение без обязательных фото запрещено. Выбранная форма и привязка сторон сохраняются после успешного сохранения и повторного открытия.

У РФ есть `Основная страница` и `Регистрация (прописка)`. Основная страница обязательна; связь обязательности фото регистрации с заполнением её полей — Q-PAS-06. Фото регистрации не становится оборотной стороной ID-карты при смене страны.

## Валидация реквизитов

| Поле | Подтверждённое правило |
| --- | --- |
| ФИО РФ | Кириллица, пробел, дефис; латиница, апостроф и цифры запрещены |
| ФИО иностранного паспорта | Кириллица, латиница, пробел, дефис, апостроф; цифры запрещены |
| Регистр ФИО | Сохраняется; строчная первая буква вызывает мягкое предупреждение, которое само по себе не блокирует сохранение |
| Место рождения РФ | Кириллица, цифры, пробел, дефис, точка, запятая |
| Место рождения иностранного паспорта | Кириллица и латиница, цифры, пробел, дефис, точка, запятая |
| Кем выдан, РФ | Кириллица, цифры, пробел, дефис, точка, запятая, `№` |
| Кем выдан, иностранный паспорт | Кириллица и латиница, цифры, пробел, дефис, точка, запятая, `№` |
| Серия РФ | Ровно четыре цифры; ведущие нули сохраняются |
| Номер иностранного паспорта | Латиница, цифры, пробел, дефис; правило реквизита рассматривается отдельно от естественных текстовых полей |
| Номер РФ | Точный формат не подтверждён — Q-PAS-02 |
| Код подразделения основного паспорта РФ | `000-000`, шесть цифр; ведущие нули сохраняются |
| Пол | `Мужской` / `Женский` |
| Дата рождения | Выбор через календарь; не в будущем; возраст 18–100 полных лет |
| Дата выдачи | Выбор через календарь; позже рождения, не в будущем |
| Срок действия иностранного паспорта | Выбор через календарь; позже выдачи; просроченный паспорт сохранять нельзя. Граница «сегодня» — Q-PAS-05 |

Отчество можно не заполнять или удалить ранее сохранённое значение. Заполненное отчество проверяется по правилам ФИО. Ограничения проверяются при вводе, вставке и через API; проверка только интерфейса не подтверждает серверную валидацию.

Разрешённый набор символов не определяет допустимость строки только из разделителей, позиции разделителей или вариантов Unicode: Q-PAS-27 и Q-PAS-28. Смешение алфавитов — Q-PAS-01; длины — Q-PAS-03 и Q-PAS-04.

## Постоянная регистрация: поля и фото

Полностью пустые поля регистрации допускаются. Заполнение любого поля, включая необязательное, активирует обязательность **даты регистрации, региона, пункта, улицы и дома**. Квартира, корпус, отделение и код структуры необязательны. Заполненные необязательные поля проходят валидацию.

| Поле | Правило |
| --- | --- |
| Дата регистрации | Выбор через календарь; не в будущем |
| Регион, пункт | Кириллица, пробел, дефис, точка |
| Улица | Кириллица, цифры, пробел, дефис, точка, запятая |
| Дом | Цифры, кириллические буквы, дробь `/`, дефис |
| Квартира | Цифры, буквы, дробь `/`; алфавит букв — Q-PAS-08 |
| Корпус | Цифры и буквы; алфавит — Q-PAS-08 |
| Отделение | Кириллица, цифры, пробел, дефис, точка, запятая, `№` |
| Код структуры | Необязателен; точное название и формат — Q-PAS-07. Не смешивать с обязательным кодом основного паспорта РФ |

Во всех строках следующей матрицы основная страница паспорта и остальные реквизиты валидны. Проверки обязательности **полей** отделены от решения о допустимости сохранения **всего документа**.

| Состояние полей регистрации | Фото регистрации | Что известно | Что требует ответа |
| --- | --- | --- | --- |
| Все пустые | Нет | Поля регистрации не обязательны | Нужно ли фото пустого блока для сохранения — Q-PAS-06 |
| Все пустые | Есть | Текстовые поля не заполнялись | Активирует ли фото обязательность полей — Q-PAS-06 |
| Обязательные заполнены валидно | Нет | Требования к полям выполнены | Требуется ли фото заполненного блока — Q-PAS-06 |
| Обязательные заполнены валидно | Есть | Полный валидный блок допускает сохранение | Нет вопроса о комплектности |
| Заполнено хотя бы одно поле, обязательные заполнены не все | Есть или нет | Сохранение запрещено из-за недостающих обязательных полей | Фото не отменяет обязательность полей |
| Все поля очищены после заполнения | Фото осталось | Условия, связанные с заполнением полей, сняты | Учитывается ли оставшееся фото как отдельное основание обязательности — Q-PAS-06 |

## Смена страны и формы

- При смене страны применяются правила новой страны. Неприменимые поля не должны мешать её сохранению.
- При успешном сохранении РФ → иностранный очищаются неприменимые серия, код подразделения и постоянная регистрация; иностранный → РФ — срок действия. Очищенные значения не восстанавливаются из старого состояния при последующих переключениях.
- Для РФ с данными и фото регистрации при переходе на иностранный паспорт показывается `Удалить страницу постоянной регистрации?`. Текст сообщает, что фото и данные удалятся после сохранения. Действия: `Отмена`, `×`, `Удалить и сохранить`.
- Подтверждённое успешное сохранение новой страны удаляет данные и фото постоянной регистрации из текущего паспорта. Отмена и отклонённое сохранение не выполняют отдельное удаление сохранённой регистрации.
- Файлы остальных неприменимых документов сохраняются; меняется их доступность по действующим основаниям.
- После успешного сохранения книжки активна одна страница, после ID-карты — две стороны. Правила переноса основной страницы, судьба оборота при возврате к книжке и подтверждение его удаления — Q-PAS-16–18.

## Ошибки и целостность: критерии QA

Это критерии проверок сохранности данных; они не являются отчётом о реализованных механизмах. Способ контроля конфликтов и конкретные ответы API требуют уточнения.

| Наблюдаемая ситуация | Что проверять |
| --- | --- |
| Ошибка чтения существующего паспорта | Ошибка не подменяется новым пустым документом; сохранение случайно не перезаписывает существующий паспорт; повторное чтение возвращает фактические данные |
| Запрос сохранения гарантированно не отправлен | Сохранённое состояние не изменилось; введённые значения доступны для повторной попытки |
| Сервер явно отклонил операцию без записи | Прежние поля, файлы, статус и дата сохранены; успешное изменение в истории не создаётся |
| Сервер сохранил, ответ потерян | Новое чтение возвращает сохранённое состояние; отсутствие ответа не считается доказательством отката; повтор не создаёт дубли операции/истории |
| Исход операции неизвестен: таймаут или неоднозначная ошибка | Сверить сохранённое состояние чтением; до этого не утверждать ни успех, ни откат |
| Сбой загрузки замены фото | Прежний сохранённый файл не утрачен из-за неуспешной замены |
| Ошибка или отмена сохранения после замены фото | Повторное чтение показывает прежнюю сохранённую привязку, если сервер не подтвердил запись новой |
| Поздние ответы загрузок или чтения | Данные не прикрепляются к другому водителю, документу, стороне или уже закрытому редактированию |
| Устаревшая форма в другой вкладке/у другого администратора | Выполнить сценарии Q-PAS-25 после согласования политики конфликтов; не назначать автоматически отказ или «последняя запись побеждает» |

Одного успешного HTTP-кода недостаточно: проверять повторное чтение документа, доступность файлов, связанную историю и список. Доступ сотрудника к нескольким водителям не означает разрешения переносить вложения между их документами; контракт привязки файлов — Q-PAS-30.

## История

Основание: [документация истории](history.md). Одно сохранение изменённых полей создаёт одну строку истории; старые/новые значения и автор относятся к фактически выполненному сохранению. Загрузка фото — `Загружено фото`, замена — `Фото заменено`. Фото истории доступны сотруднику по token/cookie админки: без авторизации `401`, с токеном водителя `403`.

Изменения из Mobile и других перечисленных в документации истории каналов не входят в scope этой истории. Отображение удаления данных/сторон и доступ к прежним вложениям после удаления уточняются отдельно, Q-PAS-21–22. Ожидание отсутствия новой записи при отказе сервера не распространяется на успешное сохранение с потерянным ответом.

## Cross-platform / Integration impact

Недоступные документы остаются видимыми в Admin Web; Mobile скрывает их по своим правилам. Файлы при блокировке сохраняются. Полное тестирование Mobile в область этой документации не входит. Изменение названия статуса в админке автоматически не меняет мобильный контракт; интеграционные сценарии и открытые зависимости находятся в [чек-листе списка](../../../checklists/admin/driver/documents-list-admin-checklist.md#cross-platform--integration-impact).
