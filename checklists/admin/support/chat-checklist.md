# Чаты — QA Documentation & Master Checklist

**Продукт:** Trade Taxi  
**Модуль:** Admin Panel  
**Страница:** Чаты / Поддержка  
**Платформа:** Web

---

# 1. Scope

Страница предназначена для коммуникации сотрудников поддержки с водителями.

Функциональность включает:

- список существующих чатов;
- поиск существующего чата по любой части ФИО водителя;
- создание диалога водителем;
- создание диалога администратором со страницы водителя;
- просмотр информации о водителе;
- переход из чата в карточку водителя;
- просмотр истории сообщений;
- отправку текстовых сообщений;
- отправку изображений;
- Reply на текстовые сообщения и изображения;
- переход из Reply к исходному сообщению;
- счётчики непрочитанных сообщений;
- фильтрацию чатов;
- пагинацию списка;
- пагинацию истории;
- real-time обновление списка и открытого чата.

# 2. Бизнес-правила

## 2.1 Список чатов

В списке отображаются только водители, с которыми уже существует диалог.

Чаты сортируются по времени последнего сообщения: **последний активный чат находится сверху**.

Любое новое сообщение — как от водителя, так и от администратора — обновляет время последней активности и поднимает чат наверх.

Для каждого чата отображаются:

- фамилия и инициалы водителя;
- аватар;
- инициалы ФИО внутри аватара;
- обводка аватара, цвет которой соответствует статусу водителя;
- последнее сообщение;
- количество непрочитанных сообщений данного чата.

Если последнее сообщение является изображением, вместо текста отображается `Фото`.

## 2.2 Поиск

Поиск выполняется **по любой части ФИО**.

Поиск осуществляется только среди водителей, с которыми уже существует диалог.

Водителя без существующего диалога через поиск на странице чатов найти нельзя.

Чтобы администратор первым начал переписку с таким водителем, необходимо перейти на страницу водителя и открыть диалог оттуда.

## 2.3 Unread

Используются два разных счётчика:

- **Счётчик в строке чата** показывает количество непрочитанных сообщений конкретного чата.
- **Счётчик в боковом меню** показывает количество чатов, в которых есть хотя бы одно непрочитанное сообщение.

Пример: в чате A — 5 непрочитанных сообщений, в чате B — 2. В строках отображаются `5` и `2`, а в боковом меню — `2`.

Сообщения считаются прочитанными **при открытии чата**.

Если входящее сообщение приходит в уже открытый чат, оно сразу считается прочитанным и не увеличивает unread counters.

## 2.4 Фильтры

Доступны:

- **Статус водителя** — множественный выбор.
- **Непрочитанные сообщения** — toggle.

При выключенном toggle фильтрации по unread нет.

При включённом toggle отображаются только чаты, имеющие непрочитанные сообщения.

Несколько `driver_statuses[]` работают как OR, а комбинация статусов с `has_unread=1` — как AND.

Применённые фильтры **не сохраняются** после reload страницы. После reload устанавливается default state.

Закрытие панели через `×` **отменяет изменения, которые не были применены**.

## 2.5 Состояние composer

При переключении между чатами:

- незавершённый текст сбрасывается;
- активный Reply сбрасывается.

Draft отдельно для каждого чата не сохраняется.

## 2.6 Ограничения сообщений

Максимальная длина текстового сообщения — **1000 символов**.

Для изображений:

- максимальный размер — **≤ 10 MB**;
- изображение размером ровно 10 MB допустимо;
- изображение размером более 10 MB должно быть отклонено;
- поддерживаемые форматы: `jpg`, `jpeg`, `png`, `webp`.

## 2.7 Reply

Reply связан с конкретным исходным сообщением.

Клик по цитате Reply должен переходить/скроллить к исходному сообщению.

Для изображения в Reply используется компактная thumbnail. Точный размер миниатюры пока не зафиксирован дизайном (**TBD by Design**).

Удаление сообщений через UI не предусмотрено.

- [ ] WEBP успешно загружается.
- [ ] Расширение в upper case корректно обрабатывается, если допустимо системой.

## 12.2 Размер

## 12.4 Отображение

# 13. Unread — строка чата

Счётчик содержит **число непрочитанных сообщений этого чата**.

- [ ] Первое unread → counter `1`.
- [ ] Второе unread → counter `2`.
- [ ] Несколько сообщений корректно суммируются.
- [ ] Сообщения администратора не увеличивают counter.
- [ ] Counter отображается на правильном чате.
- [ ] Открытие чата помечает сообщения прочитанными.
- [ ] После открытия counter строки сбрасывается.
- [ ] Reload не возвращает уже прочитанные сообщения в unread.
- [ ] Новое сообщение после прочтения снова создаёт counter `1`.

---

# 14. Unread — боковое меню

Sidebar показывает **количество чатов с unread**, а не число сообщений.

- [ ] Первое unread в чате A → sidebar `1`.
- [ ] Ещё 5 сообщений в A → sidebar остаётся `1`.
- [ ] Первое unread в B → sidebar становится `2`.
- [ ] Дополнительные сообщения B не увеличивают число чатов.
- [ ] Открытие A уменьшает sidebar `2 → 1`.
- [ ] Открытие B уменьшает `1 → 0`.
- [ ] При отсутствии unread counter скрывается/отображает 0 согласно дизайну.
- [ ] Значение корректно после reload.
- [ ] Real-time сообщения корректно обновляют значение.

### Контрольный сценарий

- [ ] A имеет 5 unread, B имеет 2 unread → строка A = `5`, строка B = `2`, sidebar = `2`.

- [ ] Sidebar counter не увеличивается.

# 17. Reply — переход к исходному сообщению

- [ ] Цитата Reply кликабельна.
- [ ] Клик переводит к правильному исходному сообщению.
- [ ] Если исходное сообщение уже загружено, выполняется корректный scroll.
- [ ] Если исходное сообщение находится на предыдущей странице истории, необходимые сообщения подгружаются.
- [ ] После подгрузки выполняется переход именно к исходному message.
- [ ] Не происходит перехода к другому сообщению с одинаковым текстом.
- [ ] Переход выполняется по ID сообщения, а не по содержимому.
- [ ] Reply на очень старое сообщение корректно приводит к нему.
- [ ] После перехода пользователь может продолжить работу с чатом.
- [ ] Переход не сбрасывает/не дублирует историю.

# 22. Комбинации фильтров

| Статусы | Unread | Expected |
|---|---:|---|
| Не выбраны | OFF | Все чаты |
| A | OFF | Чаты статуса A |
| A + B | OFF | Чаты статусов A или B |
| Не выбраны | ON | Все чаты с unread |
| A | ON | Чаты A, имеющие unread |
| A + B | ON | Чаты A или B, имеющие unread |
| Статус без чатов | OFF | Empty state |
| Статус без unread | ON | Empty state |

Логика:

- внутри `driver_statuses[]` → **OR**;
- между `driver_statuses[]` и `has_unread=1` → **AND**.

- [ ] Данные одного водителя не появляются в header другого при быстрых запросах.

# 30. Race conditions

- [ ] A → B → C до завершения requests: отображаются данные C.
- [ ] Загрузка истории A → переход B: сообщения A не попадают в B.
- [ ] Search A → Search B: поздний response A не заменяет результаты B.
- [ ] Filter A → Filter B: поздний response A не заменяет результаты B.
- [ ] Pagination + incoming message: нет дублей.
- [ ] Send + real-time echo: нет дубля сообщения.
- [ ] Два входящих сообщения одновременно: оба отображаются.
- [ ] Incoming message + смена чата: сообщение попадает правильному водителю.
- [ ] Incoming message + active filters: результаты соответствуют фильтру.
- [ ] Incoming message + unread filter: чат появляется только если фактически стал unread.
- [ ] Быстро открыть unread A → B: counters и read-state обоих чатов остаются консистентными.

# 31. Ключевые E2E-сценарии

1. **Входящее сообщение:** водитель пишет → чат поднимается → preview обновляется → counter строки увеличивается → sidebar учитывает чат → админ открывает чат → сообщения становятся read → counters обновляются.

2. **Открытый чат:** админ находится в A → водитель A пишет → сообщение появляется real time → preview обновляется → чат поднимается → unread counters не увеличиваются.

3. **Первый контакт водителя:** водитель без диалога пишет → создаётся один новый чат → чат появляется сверху → unread строки `1` → sidebar +1.

4. **Первый контакт администратора:** открыть водителя из его карточки → начать чат → отправить сообщение → чат появляется в списке → водитель отвечает в тот же диалог.

5. **Reply:** открыть чат → выбрать старое сообщение → Reply → отправить → цитата правильная → кликнуть цитату → переход к исходному сообщению.

6. **Reply + pagination:** ответить на старое сообщение → обновить страницу → открыть Reply → клик по цитате → система подгружает историю и приводит к исходному сообщению.

7. **Reply на фото:** ответить на фото → отображается компактный thumbnail → отправить → reload → thumbnail и связь с исходным сообщением сохранены.

8. **Переключение:** в A написать draft + выбрать Reply → перейти B → draft и Reply очищены → сообщение B не содержит данные A.

9. **Unread filter:** включить toggle → открыть unread-чат → он становится read → закрывается и исчезает из результатов → counters уменьшаются.

10. **Filters:** выбрать два статуса + unread → Apply → проверить API и список → открыть Filters → изменить условия → `×` → изменения отменены → reload → default filters.

11. **Pagination + realtime:** загрузить несколько страниц → получить сообщение в старом чате → чат перемещается наверх без дублей/потери записей.

12. **Лимиты:** 1000 символов отправляется → 1001 не отправляется; JPG/JPEG/PNG/WEBP размером ≤10 MB отправляется → >10 MB отклоняется.
